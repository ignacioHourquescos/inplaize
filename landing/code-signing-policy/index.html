Code signing policy

Última actualización: 10 de noviembre de 2026

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

Los instaladores de inplaize se firman con un certificado emitido a nombre de SignPath Foundation, una fundación que presta su certificado a proyectos de código abierto. Eso significa que Windows muestra SignPath Foundation como editor del archivo: no es un error, es el modelo del programa. La clave privada no la tiene nadie del proyecto, vive en el módulo de seguridad (HSM) de SignPath.

Lo que la firma garantiza es el vínculo entre el instalador y este código: SignPath verifica, de forma automática y en cada release, que el archivo salió de una compilación de GitHub Actions hecha a partir del repositorio público ignacioHourquescos/inplaize, y no de la máquina de alguien.

Cómo se compila y se firma cada versión

  1. Se publica una etiqueta de versión (por ejemplo v1.5.3) en el repositorio.
  2. GitHub Actions compila el instalador en un runner propio de GitHub, con el flujo definido en .github/workflows/release-win.yml.
  3. El instalador sin firmar se sube como artefacto de la compilación y se manda a firmar a SignPath.
  4. Un aprobador del proyecto revisa y autoriza la solicitud a mano. Ninguna firma es automática.
  5. El instalador firmado vuelve al flujo y se publica como adjunto del release en GitHub.

Roles del equipo

  • Autores y revisores: Ignacio Hourquescos (@ignacioHourquescos) — único mantenedor del proyecto, responsable del código fuente y de los scripts de compilación.
  • Aprobadores: Ignacio Hourquescos (@ignacioHourquescos) — autoriza cada solicitud de firma en SignPath.

inplaize es un proyecto de una sola persona, así que ambos roles recaen hoy en el mismo mantenedor. Si se suman colaboradores con permiso de escritura, esta página se actualiza para separar quién revisa y quién aprueba.

Privacidad

inplaize manda estadísticas de uso anónimas, que se pueden desactivar desde los ajustes de la app, y no transfiere ningún otro dato a sistemas que el usuario no haya pedido expresamente. El detalle completo está en la política de privacidad.

Licencia

Todo el código de inplaize se publica bajo licencia MIT, sin componentes propietarios ni doble licenciamiento comercial.

Verificar el archivo que descargaste

Hacé clic derecho en el .exe → Propiedades → pestaña Firmas digitales. Tiene que aparecer una firma de SignPath Foundation, y al abrirla, un certificado válido y con fecha de sellado de tiempo. Si esa pestaña no existe o el nombre es otro, no bajaste el archivo de este proyecto: descargalo de nuevo desde la página de versiones.

Desde PowerShell es una línea:

Get-AuthenticodeSignature .\inplaize.Setup.exe | Format-List Status, SignerCertificate

Versiones todavía sin firmar

La solicitud a SignPath Foundation está en trámite. Hasta que se apruebe, los instaladores publicados (1.5.3 y anteriores) no tienen firma, y Windows muestra la pantalla «Windows protegió tu PC» al ejecutarlos.

No es señal de que el archivo esté dañado ni de que tenga un virus: es SmartScreen avisando que no puede verificar quién publica el programa. Para instalarlo igual, hacé clic en Más información y después en Ejecutar de todas formas. Si el navegador dejó el archivo bloqueado, antes de eso entrá en Propiedades y tildá Desbloquear.

Para reportar un archivo que diga ser de inplaize y no verifique, abrí un issue en GitHub.
